## 2. What the project is

A design system for dubizzle Egypt (dubizzle.com.eg) that lets AI produce designs that look
human-designed, with no "AI slop", and that can be regenerated when a new release ships.

| Layer | Where | Notes |
|---|---|---|
| Tokens | `src/tokens/generated.css`, `design-kit/tokens/tokens.css` | 1,269 tokens + semantic API, generated from the `dubizzle-maple-master` monorepo (`npm run sync:tokens`) |

## 3. Ground rules (decided with the user — do not re-break)

- **Live site wins over the monorepo.** The monorepo lags production. Measure the live capture
  (`getComputedStyle`) when in doubt. Example: listing price is **charcoal**, not red.
- **Storybook and the design kit must render identically.** They implement components twice
  (CSS Modules vs `patterns.css`). After touching either, run `npm run check:parity`
  (needs both servers) — currently **31/31 identical**. Fix both sides to the live value.
- **Privacy:** account captures replace real names, phones, emails, message text and date of birth
  with sample data *before* anything is saved. Never write the account holder's real name
  into any file, log, commit or summary.
- **Post an Ad capture: "every step, never publish."** Never press Post/Post now. Upselling is
  captured by opening Sell faster/Promote on an existing ad, never paying.
- In the logged-in account never click Post now, Remove, Republish, Save changes, Send, Pay, Buy;
  don't open unread chats (marks them read); don't change settings.
- The capture Chrome profile (session cookies) lives at `~/.dubizzle-capture/chrome-profile`,
  outside the repo. Never commit or copy it.
- **Never run `npm audit fix --force`** — it upgrades vite past 6 and breaks Storybook.
- Repo must stay **private** (licensed Proxima Nova / GESS fonts, internal tokens). The current
  MIT `LICENSE` is wrong and should be replaced (not done yet).
- Don't push (no access from this Mac).

## 4. Live capture tooling

| Command | What it does |
|---|---|
| `npm run capture:live` | Plain HTTP fetch (desktop/mobile user agents) of manifest URLs |
| `npm run capture:rendered -- home motors property car-dpv [--layout=mobile]` | Public pages rendered in headless Chrome → `reference/live/<name>.<layout>.html` + `screens/<name>.<layout>.png` |
| `npm run capture:login` | Opens a plain (non-automated) Chrome on debug port 9333 — the user signs in there. `-- --check` confirms. (Automated Chrome gets "invalid credentials" from reCAPTCHA.) |
| `npm run capture:account` | Logged-in, read-only: my-ads, chat, edit-profile, settings-privacy, settings-notifications, packages — with two-layer redaction; refuses if signed out or the name can't be read |
| `npm run build:gallery` | Rebuilds `design-kit/reference/live/gallery.html` (linked from the kit as "Live screens") |
| `npm run check:parity` | Storybook vs kit computed-style comparison |
| `npm run build:icons` | React icon components generated from design-kit SVGs |
| `npm run build:templates` | Hand-built templates, then live-capture templates + index |
| `npm run check:templates` | Pixel-diff every live template against its live screenshot |
| `npm run check:captures [-- names]` | Fidelity: re-renders each saved HTML at its layout and pixel-diffs it against the live screenshot (`screens/_check/`) |

**Captures are frozen snapshots** (`scripts/lib/snapshot.mjs`): applied CSSOM rules, inlined fonts
(dubizzle draws some text via an obfuscation font — without it text shows as "AsB/I1"), inlined
images and SVG sprites, iframes (ads) replaced by pictures, timers stopped, all scripts removed.
Plain `page.content()` captures re-rendered 20–40% wrong.

URLs: `design-kit/reference/capture-manifest.json`. Helpers: `scripts/lib/{absolutize,render-helpers,redact}.mjs`.

**Captured so far (desktop + mobile):** home, motors, property, car-dpv (+ mobile app-install
prompt), my-ads, chat (inbox), edit-profile, settings-privacy, settings-notifications, packages.
Plus HTTP-fetched listing/DPV pages from the manifest.

## 7. Known gotchas

- `git stash list` in this folder has the old copy's uncommitted vite-8 bump — never apply it.
- Browser pane screenshots can be unreliable; measure with computed styles instead.
- `puppeteer-core` only resolves from inside the repo — put throwaway scripts in `scripts/.tmp-*.mjs`
  and delete them after, or import via absolute path.
- Storybook selectors in `check-parity.mjs` are auto-scoped to `#storybook-root` (otherwise they
  hit Storybook's own UI).
- Kit markup uses `<p>`/`<h3>`; always zero their margins in patterns, or kit cards grow taller
  than React ones.
